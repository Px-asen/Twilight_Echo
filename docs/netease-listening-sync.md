# 将听歌记录同步到网易云

登录内置网易云音源后，听歌记录默认同步。可在「设置 → 连接与控制 → 听歌记录」关闭或重新开启「同步听歌记录到网易云」，修改后立即生效。新配置和未包含此选项的旧配置默认开启，已保存的关闭设置会保留。设置搜索支持“听歌同步”“历史”“scrobble”等关键词。

扫码登录不可用时，可点击软件里的「使用官方网页登录」，在弹出的网易云官方页面完成登录。软件确认登录成功后，同步会复用该登录态，无需再扫码。在软件外单独登录浏览器不会把登录态传给播放器。

开启后，播放网易云歌曲或已具有 `ncmSongId` 的本地歌曲，切歌、停止、自然结束或正常退出时会提交本次实际收听时长。暂停后继续播放会合并为同一次记录；单曲循环、重播和队列中的重复歌曲分别计次。独立输出会话分别记录，同步播放组由组会话记录一次。

设置中显示正在提交的数量、最近提交的歌曲及秒数，或上报错误。“已提交”表示网易云日志接口确认接收，官方客户端的最近播放、排行和听歌足迹是否入账仍由网易云处理。

只有开启后的有效播放参与同步。旧历史不补报，未关联网易云 ID 的歌曲不提交。关闭同步或切换账号会丢弃未提交的旧记录。记录在当前进程内排队，网络失败或进程异常退出后不补传；部分成功、超时等结果不会自动重试，以免重复计次。正常退出最多等待 5 秒提交现有记录。

## 播放核心负责计时，音源插件负责提交

- `src/core/listening/ncmSync.ts` 接收权威播放会话的进度与状态，以真实时间间隔和实际进度增量共同限制收听秒数。相同的缓存进度不会刷新计时基准；暂停、缓冲及跳过的进度不累计。倍速播放记录实际经过的秒数。
- `CorePlaybackSession` 在主动跳转前读取进度，在跳转确认后发送 `playbackSeeked`；`playbackStarted` 划分显式重播，自然结束序号区分单曲循环。普通界面订阅和多个窗口都不触发上报。
- 每次记录在开始时绑定网易云账号和账号上下文。账号上下文随登录、退出及 Cookie 修改更新，普通插件设置和提交去重记录的保存不会取消听歌。发送前插件再次校验账号。
- `reportListening` 通过已有登录态调用 `/scrobble/v1`，传入歌曲 ID、实际播放秒数和总时长，使用本次记录的唯一 ID 避开网关 GET 缓存，并复用插件 RPC 与写入去重。
- `/scrobble/v1` 的 PLV、PLD 两次上传均有回执才视为提交成功；返回 `code: 200` 但包含部分失败信息时仍显示错误。
- `listeningSync.status` 是只读 Core 查询，需要 `statistics:read` 权限；开关保存在现有设置字段 `ncmListeningSyncEnabled` 中。

桌面端及独立服务器复用同一 Core 接线。Android 独立播放使用的 JavaScript 网关尚不支持 NCBL 所需的 Node 加密与压缩模块，不声明 `reportListening`；Android 遥控桌面或服务器播放时，由相应 Core 上报。

## 依赖与验证

固定使用 `@neteasecloudmusicapienhanced/api@4.36.1`，保留项目的二维码登录与网关异常补丁。上报格式来自上游 [`module/scrobble_v1.js`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/v4.36.1/module/scrobble_v1.js) 和 [`util/ncbl.js`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/v4.36.1/util/ncbl.js)。升级时继续验证两份上传回执，不以 HTTP 状态码替代。

`pnpm run test:ncm-listening-sync` 覆盖计时、暂停、跳转、重复播放、账号切换、去重、部分成功与设置交互。`verify:ncm-patch` 使用安装后的真实接口模块、加密实现和本地 HTTP 网关，只替换网易云上传传输，验证两次上传及响应缓存隔离。

验证真实入账时，在网易云账号中播放一首歌曲并切歌，查看设置里的提交结果，再核对官方客户端的最近播放、听歌排行和听歌足迹。自动化测试不会向真实账号写入记录。
