# 桌面进程的按需加载边界

添加后台能力时，把协议、身份和纯参数校验放在轻量共享模块中；仅在功能启用或任务开始时加载它的实现。进程隔离、启动握手和现有请求契约保持独立。

## 各进程何时加载功能

| 进程 | 启动时保留 | 按需加载 |
|---|---|---|
| 主进程 | 窗口、IPC、权限、配置、Core 监督和媒体协议注册 | `twilight-media` 首次上游请求加载 Undici；插件索引 URL 和官方 NCM 登录使用独立入口，避免带入索引服务和 legacy 云盘服务 |
| Core | 数据库、播放会话、配置与服务组合 | NCM 回环传输首次请求加载 Undici；远程发现 `start()` 加载 Bonjour |
| 数据库 | 数据库打开、迁移、恢复和串行请求处理 | 本轮不改变数据库生命周期 |
| 音频 | 原生绑定、能力握手、桥接与控制端口 | 本轮不改变原生音频加载时机 |
| 扫描 | 扫描任务与其音乐元数据解析依赖 | 继续由现有工作进程生命周期管理 |
| 分析 | 诊断、消息端口、原生绑定和原生分析能力握手 | `content-hash`、`library-tags`、`download-metadata` 分别加载自身实现 |
| 插件宿主 | 消息端口、诊断、权限校验和代理配置探测 | 找到可用代理后加载 Undici；只在网易云插件激活时加载 NCM 运行时 |

这里的 Undici 指项目安装的依赖包；不代表 Node 内置 `fetch` 的实现被移除。模块首次加载后仍由模块系统缓存，节省发生在该进程没有使用对应功能的阶段。

## 轻量契约与兼容入口

`src/shared/pluginHostContracts.ts` 提供插件身份、幂等键规则和 NCM 请求选项校验，不注册 Core ports，也不创建运行时。旧认证桥接与 RPC 协调器路径继续转导出原符号。

插件索引 URL 与默认值放在 `src/shared/pluginDistribution.ts`。索引服务的旧导出保持兼容；需要完整索引管理能力的调用方继续使用原服务。

官方 NCM 登录放在 `src/main/ncm/officialLogin.ts`。Electron 监督器直接导入该模块，`src/main/ncm/api.ts` 继续转导出登录函数和超时常量。登录窗口、Cookie 筛选、取消、超时和导航限制沿用原实现；主进程不再仅为注册登录入口而创建 legacy NCM API 运行时和云盘传输服务。legacy 启动分支仍使用原 API 入口。

`src/main/audio/audioServiceEnvironment.ts` 提供同步的 `audioServiceEnv()`，Electron 与 Node 监督器直接导入它；完整音频客户端的旧路径继续转导出。环境变量复制、Linux `ldd` 解析和 `LD_PRELOAD` 拼接保持原样。Core 的播放服务与主进程的 Afterglow 路径仍引用完整音频客户端，这次拆分只去除监督器为读取环境而引入客户端的依赖边。

主进程读取配置时不应导入服务实现，只为取得一个常量或纯函数。已有 Node 适配器中的 FTP、TagLib、音乐元数据、压缩包、编码及 XML 懒加载机制继续使用；不能删除仍为实际调用提供能力的适配器注册。

## 初始化和关闭

- 插件代理探测保持在插件模块执行之前。`initProxy()` 合并并发初始化，失败后允许重试；可选取消信号阻止停用期间的探测结果安装新传输。`installProxyFetch()` 仍是同步工厂，重定向、凭据头处理、WebSocket 和直连回退策略不变。
- 插件激活与停用按到达顺序串行处理；停用立即使待完成的导入失效并取消请求，再等待激活结束后清理。网易云请求上下文绑定本次激活的运行时，不能在停用后创建新实例或访问下一次激活的实例。
- Bonjour 同一目标的并发启动共享操作；变更目标和停止会使旧启动失效。停止等待未完成的加载与清理，过期加载结果不能发布公告。公告内容、5 秒发布超时和失败通道保持原有含义。
- 分析任务的动态导入完成后再次检查消息端口。端口已关闭时不开始新的文件操作；已经开始的任务沿用原处理路径。

同步工厂通过 Node 的模块缓存延迟 `require`；异步任务使用原生动态导入。不得删除模块缓存来模拟卸载，也不得使用 `moduleSideEffects: false` 掩盖初始化依赖。

## 构建与验证范围

桌面多入口构建及服务端入口继续使用既有配置和生产依赖。2026-11-08 已通过 Core、Node、前端类型检查、桌面生产构建、渲染资源预算检查，以及独立 Server 和 Windows 服务构建。

已有插件宿主、代理、NCM 登录、服务发现、分析任务、音频启动恢复及打包依赖闭合回归已通过。桌面配置导出、六会话迁移和升级回滚也通过真实 Server 入口验证。

本轮没有采集完整内存基准或首用延迟数据。内存变化应按 [桌面内存基准](./memory-benchmark.md) 的固定工作负载比较；源码中的动态导入数量不能换算为内存节省量，实际入口的静态依赖闭包仍取决于生产构建的共享块划分。

内核层面的取舍见 [Electron 43.8.1 裁剪评估](./electron-kernel-trimming.md)。
