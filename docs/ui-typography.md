# 页面文字规范与 HIG 检查

核对日期：2026-10-14。覆盖首页、资料库、流媒体、聚合歌单、电台、网络源、设置、外观、插件市场及音频处理的操作界面；页面职责与空间关系见[界面语言](./interface-language.md)。窗口内的音乐预览按预览比例绘制，代码及诊断内容保留等宽字体。

## 统一声明

字号定义在 `src/renderer/src/assets/base.css`，页面字体基线在 `assets/typography.css`。字体继续使用现有的 `--te-font-sans`，尊重用户选择。

| 用途                 | CSS 角色                  | 默认字号 | 建议字重     |
| -------------------- | ------------------------- | -------- | ------------ |
| 页面标题             | `--te-type-page-title`    | 28px     | 600          |
| 分组标题             | `--te-type-section-title` | 20px     | 600          |
| 次级标题             | `--te-type-headline`      | 17px     | 500–600      |
| 正文、标签、常规控件 | `--te-type-body`          | 15px     | 400–500      |
| 说明、状态           | `--te-type-caption`       | 13px     | 400          |
| 紧凑工具栏           | `--te-type-toolbar`       | 13px     | 500          |
| 文字旁图标           | `--te-type-icon`          | 16px     | 图标字体定义 |

字重角色为 `--te-type-weight-regular/medium/strong`（400/500/600）；标题行高 1.25，正文行高 1.5。新增界面应按文字用途选角色，避免逐页新增固定字号、独立倍率或显示字体。不要用缩小字号解决空间不足。

上述数值对应既有全局字号设置 14px，按该设置同比缩放，不修改已保存的偏好。派生字号在页面、编辑器和弹出属性边界重新计算，保证局部草稿字号也能生效。传送到窗口顶层的属性面板继续携带来源字体和字号。

## 本次调整

- 外观与设置是独立页面，只共用文字角色和材质规则。外观主题选择与操作位于自身标题右侧，短窗口仍显示页面名称；外观不显示设置分类或设置搜索。
- 共享页面样式由应用入口加载，两页首次打开时均应拥有完整布局，不能依赖先打开另一页。构建检查沿静态依赖验证基础样式，组合组件测试不能替代此检查。
- 设置按实际用途分为通用、播放、音频、歌词、媒体库、连接与控制、系统、版本与关于。播放习惯与歌曲衔接归入播放，输出设备、DSD 与 DSP 归入音频；版本信息、更新检查与项目信息单独列在版本与关于。删除重复的分类介绍，保留具体选项的必要说明。设置搜索只定位设置选项，全局命令仍可直达外观属性。
- 插件分类、搜索、详情、设置行和说明采用同一文字层级；去掉这些区域的 10–12px 微小文字。
- 外观预览下的对象工具、历史操作、状态和应用合为一行，主题制作模式采用同一规则。空间不足时对象工具横向滚动；窄窗口隐藏预览按钮的文字但保留读屏名称，保存与应用保持可达。
- 状态在窄窗口保留读屏入口。结束部件编辑时，焦点回到原对象按钮，保留未应用草稿、撤销和重做。

## Apple HIG 对照

参考 Apple 当前公开 HIG 及 iOS/iPadOS 27 发布说明。HIG 是持续更新的文档，不单独复制成一套“iOS 27 字号”。本项目为 Windows 桌面软件，采用其清晰层级、一致性、可读性与按需展开原则；CSS 像素不等同于 iOS 原生 point，不能据此宣称原生 HIG 认证。

| 原则                 | 本次落实与验证                                                                                                            |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 统一字体、清晰层级   | 共用文字角色，保持标题、分组、正文与说明的相对大小；真实渲染检查字体族和计算字号。                                        |
| 支持放大文字         | 设置、外观标题和常规工具、插件市场检查全局 14/18/28px；28px 对应基准字号的 200%。属性面板另外检查局部字号继承和弹出面板。 |
| 窄窗口适应           | 设置分类采用已有紧凑菜单；对象工具可滚动；保持标题、预览与应用入口。桌面与短、窄窗口均检查边界。                          |
| 熟悉的操作与键盘访问 | 原生按钮、选择器、焦点轮廓、读屏标签与状态反馈；保留搜索定位、Escape 返回、草稿冲突和保存失败反馈。                       |
| 按需展示             | 保留已有外观调整方式与属性展开规则，普通设置使用现有分组，避免进一步堆放卡片、边框或装饰性强调。                          |
| 材质和对比度         | 沿用统一材质声明；深浅主题检查。属性面板现有对比度测试同时运行，不对所有第三方皮肤作未验证保证。                          |

Apple 建议按平台使用默认和最小文字/控件尺寸；桌面页面采用 15px 正文与 13px 说明，不机械套用手机控件尺寸。本次不是全应用无障碍认证，也不修改第三方插件自定义内容的排版。

官方依据：

- [Typography](https://developer.apple.com/design/human-interface-guidelines/typography)：少量字体族、文字角色、放大后保持层级。
- [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)：可读性、理想支持 200% 文字放大、按平台区分默认尺寸。
- [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)：适应窗口及文字大小、清晰阅读顺序。
- [Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles)：层级、一致性与熟悉交互。
- [Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：按语义和层级使用材质。
- [iOS & iPadOS 27 Release Notes](https://developer.apple.com/documentation/ios-ipados-release-notes/ios-ipados-27-release-notes)：当前平台文档。
