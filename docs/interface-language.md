# Twilight Echo 界面语言

Twilight Echo 是让人持续聆听、整理收藏并精确控制声音的 Windows 音乐工具。界面的共同性来自阅读顺序、操作预期和状态反馈：内容先被看见，工具容易找到，操作后知道发生了什么，离开后能回到原处。

本规范负责页面空间、信息职责和交互语法；[文字规范](./ui-typography.md)、[材质契约](./material-contract.md)、[控件契约](./ui-style-unification.md)与[动效规范](./ui-motion.md)分别负责对应实现。主题可以改变情绪和布局，但不能让同一操作失去名称、焦点、可读性或返回路径。

## 1. 内容主导，工具安静

- 浏览时以封面、歌曲与收藏为主；播放时以当前作品和歌词为主；处理音频时以信号链、参数和输出状态为主。页面可以有不同结构，不能有不同的基础操作语言。
- 先用标题、顺序、间距与对齐表达分组，再决定是否需要底色和边界。外观、设置与插件市场采用开放工作区；不要给每一段内容再套卡片。
- 强调色表达主要动作、当前位置或明确状态。普通说明、工具栏和图标保持中性；错误、警告、喜欢、播放与选择分别表达自己的含义。
- 专辑封面、歌词、频谱与图表可以表现音乐情绪。常规工具栏不使用装饰性发光、循环呼吸或边缘光来争夺注意力。

## 2. 页面空间与共同边界

空间基础定义在 `assets/base.css`，页面用途与窄窗值由 `assets/page-spacing.css` 统一派生。相邻项目从 4px 网格选取间距：有关联的内容通常 8–12px，操作组之间 24px，内容章节之间 32px。光学对齐与 1px 分隔线允许偏离网格。页面 Dock 整体向下偏移 1px，保留原高度。

| 角色           | 实现                       | 使用方式                                                    |
| -------------- | -------------------------- | ----------------------------------------------------------- |
| 页面横向留白   | `--te-page-gutter`         | 24–48px 随窗口宽度变化，窄内容区域可用 16px                 |
| 内容容器上限   | `--te-page-content-max`    | 默认 1280px，居中；封面画廊和开放设置保持相同内容边界       |
| 全宽页面内边距 | `--te-page-inset`          | 同时计算留白和居中容器外侧空间，避免不同页面自行估算比例    |
| 页面顶部留白   | `--te-page-top`            | 内置外壳内容槽内 32px；标题栏高度由外壳预留一次             |
| 页面底部安全区 | `--te-page-bottom`         | 实际播放栏遮挡高度加 24px，至少 32px                        |
| 内容组与章节   | `--te-space-group/section` | 24/32px；紧凑密度改变行、卡片和组内间距，不移动整个页面边界 |

内容宽度和字体一起决定何时换行，不按手机、平板或桌面名称硬分断点。缩小时先让说明换行、元数据省略、工具组滚动或按既有规则收纳；不要缩小字号或挤掉播放、返回、应用入口。长窗口不把表单和正文无限拉宽。虚拟列表的行高、占位高度和可见范围必须使用同一字号尺度。

### 页面内边距契约

下表数值是内容槽内的 CSS px。窗口宽度不超过 680px 时使用窄窗列；标题栏由外壳或独立浮层预留一次，不计入表中的顶部留白。

| 页面范围                                                          | 横向 / 顶部 | 窄窗横向 / 顶部 | 底部与嵌套规则                                                                             |
| ----------------------------------------------------------------- | ----------- | --------------- | ------------------------------------------------------------------------------------------ |
| 本地歌曲、专辑、歌手、流派、文件夹、收藏、应用/聚合歌单、最近播放 | 24–32 / 24  | 16 / 16         | 实际播放栏遮挡 + 24，至少 32；歌单与最近播放由上层放置页签，下层仅保留 16px 组内间隔       |
| 所有音源的推荐、发现、音乐库、云盘、搜索与详情                    | 24–32 / 24  | 16 / 16         | 同资料库；标题、搜索与内容共享左右边界，详情不再叠加页面留白                               |
| 默认主页、听歌统计、电台播客、网络源、插件市场、插件扩展页        | 24–48 / 32  | 16 / 24         | 1280px 内容上限；完整宽度页面通过 `--te-page-inset` 居中，主页以容器宽度居中，避免两次收窄 |
| 音频处理工作区、独立均衡器与效果链                                | 24–48 / 32  | 16 / 24         | 工作区放置共同标题；嵌入式均衡器/效果链不再次预留标题栏或横向页面边距                      |
| 设置、外观选择与自定义编辑器                                      | 24 / 24     | 16 / 16         | 设置底部 48（窄窗 32）；外观底部 8，固定操作带另行预留实际高度，保持开放工作区             |
| 独立主题插件工坊                                                  | 24 / 24     | 16 / 16         | 自己预留标题栏；嵌入式工坊、主题画布与属性列使用编辑器内部间距                             |

播放详情采用沉浸式封面/歌词布局；账户与登录使用锚定弹层或登录舞台；引导页、主题提供的主页版式和自定义外壳属于专用布局。这些页面保持已有专用边距、滚动与安全区域，不把普通内容页的外边距再叠在里面。卡片、对话框与浮层不是页面边界。

默认内置外壳以本地音乐内框为颜色基准：`main.css` 的 `--te-content-panel-tint` 保留本地原叠层，`--te-content-panel-solid` 用相同叠层与 `--te-local-bg` 合成流媒体内框底色；浅色资料库原有纯白底由共同的 `--te-library-light-panel-bg` 提供。深浅色与本地颜色变化都实时派生，流媒体子页不得另加普通页面底色。独立背景草稿、背景图片、透明窗口与主题自定义外壳继续由原背景/主题契约控制；不修改保存的主题格式或覆盖用户配置。

本地资料库以连续检索和批量整理为主，使用完整可用宽度，横向留白为 `clamp(24px, 2vw, 32px)`，外壳内容槽内顶部留白为 24px。歌曲、专辑、歌手、流派、文件夹、歌单、收藏与最近播放沿用这一条内容对齐线，包装页面不再叠加内边距。页面标题及数量先出现，播放、整理、筛选和搜索按任务分组；缩小时允许工具换行，文字保持用户设定的尺度。

字号 14px 时，本地歌曲默认行高 56px、紧凑行高 48px。复选框出现后保留封面与文字列的位置。行高随文字增长，虚拟滚动、上下占位和键盘定位使用同一实测尺度。封面网格按实际容器宽度与集合数量共同计算列数，卡片在尺寸范围内均分每行空间：常规 160–220px，窄容器 128–200px，紧凑模式 140–190px。六项等不足容量的数据也会在上限内适当扩大，只有一两项时靠左排列并保留正常间距。列数与卡片高度变化后重新测量虚拟步长，避免末项空洞与返回错位。专辑详情使用 160px 封面，短窗或窄窗使用 120px。分类名称、作品标题与元数据继续使用共同的文字角色；标题截断后保留完整名称。A–Z 索引只在集合足够长且具备多个可索引字母时显示，中文名称沿用拼音首字母。

左侧导航与右侧当前队列覆盖内容，打开时不改变主内容宽度。层级为播放栏 > 侧栏与遮罩 > 主内容。遮罩可关闭相应面板；关闭后焦点回到打开它的控件。当前队列保留稳定条目标识、虚拟滚动、撤销和来源信息。

## 3. 文字有职责

全局字号设置 14px 时，页面标题 28px、分组 20px、次级标题 17px、正文 15px、说明与状态 13px。全部从既有字号设置派生，具体字体尊重用户选择。常规界面字重使用 400/500/600；不要用 800/900 与微小大写文字制造层级。

页面、列表标题、字段、状态与工具都使用语义角色。封面上的作品展示字、沉浸歌词、谱线刻度和代码诊断可以保留专项排版；例外应服务内容，不成为第二套页面字体。需要阅读并据此操作的名称、错误与说明不能作为图表刻度例外。

文字放大时增加行高、允许换行或改变布局。播放时长可以压缩可视文字，但进度条保留可用空间，读屏仍得到完整时长。使用省略的标题必须保留原文及可访问名称。

## 4. 控件、状态与键盘

按钮、选择器与输入框使用现有原生语义及控件尺寸角色。图形尺寸和命中区域分开处理；小图标不意味着小按钮。不要强迫所有控件采用同一种外形：播放可以是胶囊，参数可以是输入框，开关保持二态语义。

| 状态      | 表达                                             |
| --------- | ------------------------------------------------ |
| 焦点      | 键盘所在位置，明确轮廓，滚动到可见区域           |
| 选择      | 批量操作目标；歌曲列表空格切换，不自动播放       |
| 播放      | 当前发声的歌曲、队列条目或音源；独立于焦点与选择 |
| 悬停/按下 | 即时局部反馈；父行不随内部按钮重复缩放           |
| 忙碌      | 保留动作位置，给出状态，防止重复提交             |
| 禁用      | 说明条件，禁用后不触发动作；不能只降低透明度     |
| 错误      | 在动作附近给出原因与恢复入口，不仅改变颜色       |

- 歌曲表格保留表格语义。行获得焦点后 Enter 播放，空格切换选择；内部歌手、专辑、复选框和菜单继续拥有各自键盘行为。单击/双击偏好只影响指针激活方式。
- DSP 节点 Enter/空格选择，↑↓移动焦点，Alt + ↑↓ 调整顺序。拖拽与键盘使用同一移动操作，操作后保留节点焦点，并宣布新的位置。
- 按钮优先使用 `button`，可见名称优先于仅图标；仅图标必须有名称。快捷键提示不能代替可发现的操作入口。
- Escape 先关闭最上层临时面板，再走已有页面返回栈。不要叠加另一套全局返回监听。
- 持续状态使用适当的 `status`/`alert` 语义；不把播放进度每帧播报给读屏。焦点不可被固定播放栏、侧栏或浮层遮住。
- 焦点使用独立的 `--te-control-focus-color`，浅色为深蓝、深色为天蓝；切歌、封面取色和用户强调色不改变键盘位置的表达。强制颜色模式使用系统 `Highlight`。强调底色上的文字与图标使用配对的 `--te-control-on-accent`。
- 手动浏览歌词后提供“返回当前歌词”，只恢复跟随，不跳转播放时间。保留既有自动恢复；自动恢复不能删除仍持有键盘焦点的入口。

## 5. 页面家族与允许的差异

| 页面家族                       | 保留的结构                                     | 共同约束                                                                       |
| ------------------------------ | ---------------------------------------------- | ------------------------------------------------------------------------------ |
| 首页与资料库                   | 编辑式推荐、封面网格、歌曲表格                 | 共同的标题、操作与底部安全区；资料库按检索任务采用更宽内容区，切换视图保留位置 |
| 流媒体、聚合歌单、电台与网络源 | 来源能力和加载方式各自独立                     | 相同文字、状态与播放反馈；空、加载、失败、不可播放必须可区分                   |
| 设置、外观、插件市场           | 设置分类、外观预览与属性、插件开放列表各自独立 | 相同文字与控件；外观不嵌入设置导航，不丢失未应用草稿                           |
| 音频处理                       | 信号链、曲线、参数与试听工作区                 | 可读的参数、键盘路径、单位与明确的应用状态；精确输入不依赖拖拽                 |
| 播放详情与三种播放栏           | 详情沉浸；标准栏可用材质；迷你与紧凑栏平面化   | 图标语义、播放/暂停、进度、喜欢、队列、焦点与错误一致；不强制同一几何外壳      |
| 主题制作与插件工坊             | 编辑器专用工作区                               | 草稿、撤销/重做、保存/应用、关闭后焦点遵循同一预期                             |

外观底部的对象、历史、状态与应用保持一条操作带。空间不足时对象工具横向滚动，应用入口保持可达。只在“主题插件工坊”显示对应 BETA 标识。

头像入口先展示账户与活动概览，保留可见标题、清楚的来源状态和登录入口；指定来源的登录深链可以直接进入该来源。账户面板附着于头像位置，使用实际播放栏遮挡计算可用高度，内容超出后在面板内滚动。视图切换不丢失有效焦点，关闭后按触发方式恢复焦点；不为恢复表单新增密码或验证码持久化。登录方式与来源能力保持独立。

插件市场与设置共用开放工作区的标题、搜索、分组和中性工具语言。市场条目在适合说明与操作的宽度范围内分列，标题、筛选、状态和条目保持相同对齐线，短窗口让整页内容自然滚动。加载、失败、没有内容和筛选无结果分别说明；更新列表遵循当前搜索，操作期间保留忙碌反馈并防止重复提交。普通按钮使用共同小圆角，插件的信任、权限与安装状态继续清楚表达。

设置分类、搜索、折叠与上次位置保持稳定；分组标题强于字段标题，说明使用共同次级文字角色。放大字号时，选择器、输入框与操作区域一起增高或换行，不能仅增加文字而保持固定高度。普通设置用开放分组与分隔线表达层级，音频信号预览保留真实状态与操作，重复的参数说明不再另套展示卡片。独立外观编辑器与任务预览遵循各自结构。

本地资料库以 Apple Music 的内容秩序为视觉参照：标题与数量左对齐，常用操作和搜索形成稳定工具栏；歌曲表格连续排列，专辑列保留稳定比例。封面承担视觉重点，卡片不再套第二层玻璃外框，缺失封面使用中性底色。默认工具、搜索和专辑操作采用克制的小圆角，移除专辑取色光晕、彩色行描边与悬浮阴影。播放用图标、标题与轻底色表达，选择保留独立指示，焦点保留清楚轮廓。深浅主题、紧凑密度和既有布局沿用同一语义与公共主题参数；这些规则不要求复制 Apple 的平台控件或覆盖用户自定义皮肤。

流媒体推荐、发现、在线音乐库、收藏专辑与歌手、搜索和详情沿用资料库的完整宽度与 24–32px 横向留白。子页面不再重复叠加外框、居中窄列或页面内边距；首页摘要不占据大半首屏，发现页第一张封面与其他项目保持相同尺寸。封面共用上述有界网格，条目较少时靠左；带三首预览的排行榜矩形在 280–480px 内分列。字号随设置增长，缩窗时改排列与披露方式，不缩小文字。曲目焦点、选择、正在播放和喜欢继续独立表达；嵌套下载、收藏和菜单不会误触整行播放。

去除重复外框不等于去除内容分组。推荐首页的每日推荐与电台入口使用圆角矩形卡片，表达不同的播放任务；卡片沿用共同内容材质，封面与文字各有稳定区域。歌曲速览在足够宽的窗口采用三列，缩窗或文字需要更多空间时减少列数，不把三列当作所有设备的固定要求。在线音乐库先提供紧凑身份与喜欢、最近、排行入口，主体按歌单、专辑、歌手切换；默认歌单，其他受支持类型保持可见，避免先铺完全部专辑再到歌单。同一音乐库内切换类型保留有效筛选、已显示数量与加载结果；从详情返回保留类型、歌单筛选与已展开数量。切换音源、账户或登录状态时清除上一身份的视图状态。

搜索页把查询作为主要任务：标题下提供可见输入，结果类型与音源范围紧邻查询，结果沿同一内容边界展开。来源范围和结果类型是两个不同维度，必须各自清楚标注；清除后回到输入，继续查找不需要重新定位。初始提示、加载、无结果与失败分别呈现；没有真实数据契约时不添加虚构热搜或搜索历史。可见输入与明确范围来自搜索设计原则，具体字段宽度、圆角与分列属于本产品根据实际窗口校准的选择。

Provider 决定来源能力、数据与品牌元信息，宿主负责共同页面结构。两种首页适配、发现、音乐库、搜索、曲目与艺人详情、下载任务使用同一套标题、工具与状态语言；不为品牌色新增整套页面配色或任意 HTML/CSS。登录、分类、排序、收藏与详情入口按真实能力和方法开放，歌单搜索依据搜索能力，不能误要求歌单管理能力。云盘与部分社交操作目前是网易云专有页面，不因公共方法名称存在就宣称所有来源可用。未登录、首次加载、空集合、筛选无结果、失败与恢复中的内容分别表达，加载阶段不先显示空集合。

音频处理从顶栏明确标注的 DSP 入口进入二级工作区，均衡器与效果链同级切换。播放栏专注于持续播放，不显示 HiFi 控制台或均衡器入口；旧主题中保存的控件标识继续读取，但不渲染这两个旧入口。工作区用曲线、参数和开关表达功能，避免仪表装饰、重复卡片与发光。总 DSP 与均衡器分别保留开关状态；总 DSP 关闭时说明调节不影响听感。提交或切换期间暂时锁定编辑与内部返回，离开均衡器先等待提交，效果链草稿须保存或还原后再离开。

## 6. 材质与动效边界

材质使用既有九种角色，由 `src/shared/materials.ts` 统一决定底色、实色回退、文字、边界、阴影与滤镜。页面决定布局，材质不修改几何。禁止为本规范增加一套相似的玻璃配方。

对比度检查最终合成结果，包括封面背景、透明叠层和深浅主题。模糊不等于足够的对比度；减少透明度、高对比模式与渲染降级继续由材质契约处理。正文以 4.5:1、必要图形与焦点以 3:1 为检查目标；用户自由配置和第三方皮肤须按实际结果核对，不能宣称全部组合已认证。

动效表达动作结果和空间关系，沿用现有 press/hover/panel/page 等时间角色。CSS 缓动、Vue 过渡与弹簧都可以使用；要求是输入后即时反馈、可以中断、不会影响布局或阻塞下一次操作。不要要求所有交互都用弹簧或所有页面都做匹配几何。

减少动效时取消位移、缩放和持续装饰，保留必要状态变化。自动隐藏播放栏时，键盘焦点、打开的面板和正在拖动进度都应保持操作可达。歌词与频谱遵循真实播放时钟，不能以装饰定时器伪造播放状态。

## 7. Windows 窗口与浮层

视觉强调、应用内部层级、原生窗口顺序和输入模态是四种独立关系。主窗、独立迷你播放器、登录窗口与模态对话框遵循各自生命周期，不以增大阴影或 z-index 代替原生窗口行为。迷你播放器共享播放状态，默认不置顶；切换窗口不重开音频会话。

模态只阻止对应范围的输入，Escape 关闭最上层，关闭后恢复有效触发对象的焦点。对话框与菜单不会因为获取焦点而暂停音乐。窗口恢复遵循实际工作区约束；多屏移除、不同缩放和系统颜色变化要按真实环境分别验证。

## 8. 验证与依据

布局验证覆盖默认桌面、最小窗口、短窗口和更大的文字，至少检查深浅主题、最后一项滚动可达、播放栏实际遮挡和侧栏开合。使用真实组件与 Chromium 计算布局，交互验证包括原生键盘、指针拖动、嵌套控件与焦点返回。源码检查和截图各自不能替代另一种证据。

外部参考《Apple Music 设计比例与 Windows 迁移指南 v1.1》用于提取内容优先、分组、平台适配与可访问性原则。文档中的 224px 导航、80px 播放栏、56px 行高以及重绘的 Windows 示意图属于迁移建议，并非 Apple Windows 实现的权威参数。手机 point、Windows DIP 与 CSS px 也不能直接等同。
