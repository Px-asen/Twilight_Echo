# 统一材质声明

材质描述表面怎样透出背景、保证阅读和表达层级。颜色主题、控件几何、背景图和材质分别负责不同问题，不再用“玻璃卡片”代替所有表面的定义。

默认角色声明源是 `src/shared/materials.ts`。`generate:materials` 从它生成运行时 `assets/materials.css` 和插件可读取的 `packages/plugin-api/material-contract.json`。外观编辑器的部件覆盖保存在现有 `appearanceLayers.scopes[part][tone].material` 中，由同一运行时用于正式窗口和预览。`material-language.md` 保留光学实现和历史依据，本文规定新增界面如何接入。

## 按职责选材质

| 角色         | 用途                     | 光学玻璃         | 全局透明模式                   |
| ------------ | ------------------------ | ---------------- | ------------------------------ |
| `canvas`     | 页面底图与底色           | 无               | 可透出底图                     |
| `content`    | 专辑、歌单和正文卡片     | 部件编辑可选     | 可透明，保留编辑器调节         |
| `navigation` | 左导航、右播放队列       | 可选             | 可透明                         |
| `titlebar`   | 附着窗口的标题栏         | 可选             | 可透明，沉浸页不重复绘制       |
| `panel`      | “我的”子页面、阅读面板   | 无               | 保留可读基底                   |
| `popover`    | 外观工具、筛选及锚点浮层 | 常规扩散，无折射 | 保留可读基底                   |
| `dialog`     | 模态确认和编辑           | 无               | 保留不透明基底                 |
| `transport`  | 标准播放栏               | 可选，无边缘高光 | 详情页透明；迷你与紧凑保持平面 |
| `control`    | 字段与紧凑控件           | 部件编辑可选     | 保留可读基底                   |

所有角色都有 `background / solid / ink / border / shadow / filter` 六个字段。`solid` 是关闭透明度或特效时的明确回退，不从半透明颜色猜测。遮罩统一使用 `--te-material-scrim`。透明模式不会让对话框、账户内容或浮层失去可读基底。

## 接入方式

```html
<section class="te-material account-panel" data-te-material="panel">…</section>
```

`.te-material` 只应用材质，不设位置、宽高、圆角、边框宽度或动画。组件继续负责这些几何与交互。迁移现有组件时可只加 `data-te-material`，再在作用域样式中消费 `var(--te-material-background)` 等字段；这样保留现有绘制层和布局。标题栏的背景绘制在子层上，播放栏折射在独立 warp 层上，不能对根容器重复添加玻璃。

字段在实际绘制元素处解析；局部页面、预览深浅色与插件主题的变量覆盖不会被根节点提前计算吞掉。现有 `--te-card-*`、`--te-chrome-*`、液态玻璃设置和已保存主题继续有效。插件可消费角色，修改现有主题输入；宿主拥有材质配方与性能边界。结构化主题 token 的写入白名单保持原有契约，不把内部配方变量自动开放为可保存 token。

`resolveMaterialMode` 是光学资格与回退决策入口。关闭模糊、减少特效、减少透明度或提高对比度时使用标准基底；强制颜色使用系统 `Canvas / CanvasText`。CSS 对相同条件提供直接回退，不依赖每个组件各自监听系统设置。

外观调整工具将局部 `--te-editor-panel` 和 `--te-settings-text` 映射到已有主题输入，再消费 `panel` 字段；弹出的更多参数使用同一实色基底，外层只负责定位，避免重复叠加材质。切换预览深浅色继续跟随编辑器上下文。

## 部件材质调节

控件、侧边栏、标题栏、播放栏、卡片统一提供跟随主题、纯色、毛玻璃、液态玻璃。底色来源、底色浓度、背景模糊、饱和度和折射强度按部件与深浅色独立保存，不改写旧的全局玻璃开关。底色覆盖与旧主体颜色分开保存，切回跟随主题不会把一次材质调色变成所有控件的永久实色。

图片配色只给中性基底轻微染色，导航面板与展开按钮共享表面和滤镜；没有自定义卡片的图片页面默认使用透色与背景扩散。部件显式覆盖优先，完整 PNG 皮肤保留自己的绘制优先级。调节面板自身保留稳定、可读的实色，不随正在编辑的材质透明。

部件覆盖的公共渲染入口是 `app/componentMaterials.ts`。液态玻璃使用每种部件共享的一条小型静态 SVG 折射滤镜；不建立逐卡片贴图、指针监听或几何观察器。减少特效、关闭模糊、减少透明度、高对比度和系统强制颜色统一回退。旧的播放栏光学实现与无边缘光规则保持有效。

## 防止再次分散

- `generate:materials` 更新生成文件；`verify:materials` 检查文件一致性、角色名称与独立材质声明。正式构建先运行它。
- 新组件不能自行拼写模糊、阴影、渐变和表面颜色配方；直接硬编码纯色背景也会失败。确需新职责时先扩展中央声明，并验证两个主题、三种模式、关闭特效、可读性和输入行为。
- `scripts/material-legacy-baseline.json` 是已有独立声明的迁移清单，**不是新增材质的许可名单**。新文件、不同数值或重复添加都会失败；删除旧声明可以通过。正常检查不会重写它，捕获命令在文件已存在时拒绝运行。
- 存量主题布局、播放器光学层及页面装饰保留，按职责逐步迁移，避免一次性改变已保存主题与背景编辑。已有例外的数量会由检查输出；不要把“检查通过”解释为每个历史声明都已经迁移。

## 设计依据与验证

参考 [Apple HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：内容保持清晰，导航与浮动控制承担材质层级，复杂背景优先保证阅读。这里的 Web 配方属于应用实现，不宣称与系统材质视觉等价。

回归覆盖两种主题、三种模式和正常／关闭模糊／减少特效，共 162 个实际 Electron 渲染情形；另有 54 个 Chromium 无障碍媒体模拟情形，验证减少透明度、提高对比度和强制颜色的优先级。还验证局部变量、外观卡片输入、组件几何和点击不被材质改变。既有标题栏、账户子页面、播放栏和外观草稿测试继续约束行为。

配置页的背景阅读处理由 `readingMaterialTreatment` 统一决定：纯色 12px / 80% 淡化、毛玻璃 20px / 70%、液态玻璃 28px / 62%、全透明 24px / 60%。处理只作用于图片绘制层，进入外观、设置和 DSP 时启用；退出或全窗口外观预览时撤销。图片参数、文字和效果样本不被改写，纯色及加载失败的回退背景保持原色。
