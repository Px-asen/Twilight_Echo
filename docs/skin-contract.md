# 整体皮肤契约

本契约约束 Twilight Echo 的主题、个人皮肤、主题编辑器和预览。它补充现有主题版本，不另建一套外观设置。界面层级来自用户明确的整体背景／圆角内框设计；层级、可读性、渐进展示和可操作性参考项目的 Apple Music Windows 设计文档与 Apple HIG。具体尺寸和 UV 参数是本产品选择。

## 1. 一张整窗背景，其上一个圆角内框

| 范围           | 公共标识      | 几何与职责                                                                                                      |
| -------------- | ------------- | --------------------------------------------------------------------------------------------------------------- |
| 外框／整窗背景 | `outer-panel` | 从窗口左上角开始，覆盖整个客户端区域，包含标题栏，不是外围一圈窄边。整张 PNG 只映射一次；镂空与半透明像素保留。 |
| 内框背景       | `inner-panel` | 标题栏下的圆角内容矩形，承担页面内容的背景、图片与明暗。原“背景”与“内面板”是同一编辑入口。                      |
| 侧栏           | `navigation`  | 导航覆盖在内容上，展开与收起不改变整窗皮肤的尺寸或映射原点。                                                    |
| 标题栏部件     | `material`    | 标题栏的操作控件以及用户明确设置的独立材质／皮肤。未单独设置时透出整窗皮肤，不能再叠一张整体 PNG。              |
| 播放栏         | `player-bar`  | 浮动播放部件自己的背景与出框皮肤，文字、播放控制与进度操作位于图片之前。                                        |
| 卡片           | `card`        | 内容卡片自己的可选皮肤，服从相同的图片与交互约定。                                                              |
| 通用控件       | `controls`    | 共享颜色、材质与原有颜色效果；不向每个按钮、输入框重复贴部件 PNG。                                              |

默认布局的内框使用现有 `--te-window-content-top`、`--te-window-surface-inset`、`--te-window-content-bottom` 几何，圆角来自 `appearanceLayers.innerRadius`。布局插件继续遵守现有壳层契约。播放详情的既有沉浸模式保留其布局，不强制套入内容圆角。

`appBackground` 是已有背景与按页继承数据。原有主题不因新增皮肤被重新排版；显式设置整窗皮肤时，预览中的旧壁纸不能遮住整窗图案，内容背景应位于圆角内框范围。旧 `background` 选择／导航值兼容指向 `inner-panel`，不能成为第二个独立编辑对象。

PNG 镂空表示绘制 alpha 保留，不增加不透明底色。是否透出桌面由现有 Windows 窗口透明能力和用户设置决定；皮肤不改系统透明设置，不改变窗口点击区域。

首页主卡、在线歌单和本地收藏沿用同一个 `card` 范围；卡片同时具有多个兼容类名时只绘制一次，封面子节点不再重复贴整张皮肤。加载骨架不参与卡片皮肤，正在刷新的真实内容保留皮肤。静态主卡不增加可点击的悬停反馈，禁用卡片不响应；透明材质下的可操作卡片沿用音乐列表悬停颜色，不叠加升起或阴影。

## 2. 部件背景皮肤与 UV

每个范围在 `light`、`dark` 下有独立的 `body`、`effect`、`skin`，存储仍为 `appearanceLayers.version = 1`。旧字段继续读取，新字段缺省关闭。

```ts
skin: {
  enabled: boolean
  image: string
  opacity: number // 0–100，默认 100
  scale: number // 20–300，默认 100
  x: number // 部件宽度百分比，−100–100
  y: number // 部件高度百分比，−100–100
  placement: 'inside' | 'outside' // 默认 outside
  fit: 'fill' | 'contain' | 'cover' // 默认 fill
  frame: {
    top: number
    right: number
    bottom: number
    left: number
  }
}
```

`frame` 四边为原图的 0–45%，默认 0。扣除四边后，中间矩形映射到部件主体；四边区域可向主体之外延展。整张后期制作的 PNG 可以直接以大小、位置控制；有特定 UV 模板的 PNG 可指定主体边界。`inside` 受部件圆角裁切；`outside` 可越过部件和父容器，最终仍受应用窗口边界约束。

主体图片位于原生文字、按钮、焦点和状态标识后面。出框通道仅绘制主体外的像素，不能把 PNG 再盖到自己的前景。透明度只影响皮肤。上传不附加底色、光晕或模糊，导入 PNG 不走封面的 JPEG 缩略图流程。

显式设置的部件主体色和 PNG 优先于通用卡片材质及透明预设的默认背景规则；清除部件设置后恢复通用材质。背景文字的明暗选项只控制页面正文与说明，带实色底的首页播放按钮和封面播放标记保持成对的前景／底色，不能随正文一同变成同色。

只有现有本地导入接口返回的安全 `background://` 图片句柄能进入 `skin.image`；归一化会拒绝远程地址、脚本和任意文件路径，并限制数值。旧非控件 `effect.image` 可在没有显式 `skin` 时一次迁移；通用控件旧图片停止绘制，旧颜色效果继续兼容。

## 3. 图标是语义资源，不是按钮皮肤

图标通过 `ThemeIconSlot` 绑定功能身份。导航、标题栏、资料库和共享播放控件使用同一受控槽注册表；播放／暂停、音量／静音、收藏和播放模式等状态使用各自槽。替换图标不修改按钮标签、快捷键、焦点顺序、禁用状态或点击范围。Windows 最小化、最大化、关闭继续使用现有窗口控件。

个人主题可保存 `iconBindings: Partial<Record<ThemeIconSlot, string>>`。值必须指向该主题 `assets` 中的 `image` 类型素材 ID，不接受地址或 CSS 选择器。素材使用既有导入、哈希存储和 `theme-asset://` 协议；按比例完整显示，保留 PNG／WebP 的透明通道。没有绑定或图片加载失败时显示原图标，不能留下空白按钮。

编辑器按功能分组，提供原图／替换预览、已有素材选择、上传和恢复单项。默认 `icons.family` 的描边／粗线／填充能力保留。工坊沿用声明式受控图片槽和现有编译器，旧项目和插件不能因增加槽而失效。

## 4. 2D、3D 与实际应用一致

三种视图读取同一草稿和相同的安全归一化结果，不各存一套比例。2D 使用真实窗口部件；3D 使用真实部件的平面与纹理。整窗、内框、导航、标题和播放等平面分别保持其几何，图片主体和出框部分随所属平面变换，不能固定贴在视口上。

外观预览复用默认首页的纯展示组件，以静态示例歌曲提供主卡、最近播放和本地收藏。它不挂载音源、账户或个人资料库的加载流程；预览操作不触发播放、登录、搜索、网络请求或设置写入。

镜头旋转、缩放、展开层和悬停不写皮肤设置。图片参数变化应即时更新现有平面，不能留下旧图或重复纹理。去掉皮肤、换主题、隐藏预览和销毁编辑器时清理绘制与资源；没有启用图层时不持续测量，隐藏页面停止刷新。动态继续遵守减少动画和关闭动画设置。

鼠标视差属于 3D 预览：完整动效下跟随画布指针，进入工具、拖动或离开画布时归零；减少／关闭动效时停用。默认 2D 预览保持平面。视差只叠加于手动镜头角度，不改变角度读数、缩放、部件参数或草稿。

## 5. 编辑器使用自己的可读颜色

编辑器工作区沿用应用背景，只以中性控件区分工具。自定义选项的正文、说明、边界、选中和焦点各用明确的编辑器颜色，启用项不能看似禁用。深浅主题均要求普通文本与实际底色对比至少 4.5:1，必要的控件边界和焦点至少 3:1；禁用项通过状态与降低强调表达。

编辑器颜色不能写回主题令牌，也不能污染 2D／3D 的被编辑内容。画布中的皮肤不作用于编辑器工具，标题栏搜索、上传按钮和主题操作保持清晰、可达。

## 6. 草稿、保存与资源边界

编辑、上传、恢复默认和图标替换属于同一草稿历史；应用前不写确认设置。导入忙碌期间保护应用、离开与主题切换，失败／取消／迟到结果不覆盖新目标。放弃草稿恢复原主题，个人主题的修改不能写到其他主题或全局图层。

深浅预览只选择当前编辑的主题变体。应用后，编辑会话必须保持刚保存的变体，主题切换广播不能把深色预览退回浅色；退出编辑后恢复应用原有的深浅偏好。保存两个变体时分别写入其覆盖值，不因切换预览改写全局深浅设置。

个人主题图标的 `assets + iconBindings` 随保存、复制、历史和主题归档往返；导入时重新验证类型、存在性与受控槽。已有 `background://` 部件皮肤仍是本机背景资源；当前归档只打包 `profile.assets`，不会自动把这些本机背景复制到另一台设备。主题作者不能据此声称完整皮肤图片已可跨设备携带。

## 7. 验证门槛

修改绘制或映射时，应验证真实 RGBA 的透明／半透明／不透明像素、前景文字与按钮、内部裁切和父容器外溢；整窗图必须在标题区与外沿连续可见，内框仍独立。预览需覆盖 2D／3D、深浅色、短窗／窄窗与大字号，并检查实际修改 UV 后的更新。

修改图标契约时，应验证合法与非法绑定、素材损坏回退、状态切换、共享播放控件、恢复、草稿历史以及真实主题归档往返。受控组件测试不能替代实际 Windows 窗口检查；没有实机证据的范围应明确记录。

相关数据定义见 `src/shared/appearanceLayers.ts`、`src/shared/theme.ts`；编辑与渲染说明见 [外观面板与背景皮肤](appearance-panel-layers.md) 和 [编辑器引擎](appearance-editor-engine.md)。
