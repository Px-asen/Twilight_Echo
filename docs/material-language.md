# 界面材质语言

2026-10-15 更新：按用户要求，内容卡片和控件现在支持独立选择毛玻璃、液态玻璃。以下“不对内容卡片启用光学”的段落属于历史记录，现行覆盖规则见 [部件材质调节](./material-contract.md#部件材质调节)。新增实现使用共享静态滤镜，不恢复历史逐卡片贴图与指针采样。

新增界面的规范入口是 [统一材质声明](./material-contract.md)。角色、配方、资格与回退统一来自 `src/shared/materials.ts`；本文保留光学实现与研究记录，不另行定义一套材质。

Twilight Echo 的界面材质由透色的玻璃体、弧面的边缘和有方向的光组成。目标是让紧凑控件具有体积与层次，同时保留现有配色、字体、卡片轮廓和 Windows 操作习惯。实现文件和变量使用内部代号，产品界面沿用“液态玻璃”。播放栏采用安静的透色基底与外侧阴影，不绘制边缘高光、肩部亮面或反光贴图。

## 研究依据

- [Apple HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：玻璃用于浮动控制和导航层，内容保持清晰；常规材质与透亮材质按阅读需求区分。
- [WWDC25 Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)：阴影、折射与散射共同表现体积，尺寸不同的形体需要不同光学处理。
- [WWDC26 Platforms State of the Union](https://developer.apple.com/videos/play/wwdc2026/102/) 22:43–23:09：新一轮 Liquid Glass 调整强调暗边、局部亮高光以及复杂背景下的扩散。
- [Windows Layering and elevation](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/layering) 与 [Acrylic](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic)：用轮廓和阴影交代层级，并保证透明背景上的可读性。

以上用于建立原则。本应用使用 Web 渲染实现，尚不模拟真实光线追踪或系统原生材质。

## 共同规则

| 层             | 职责                   | 第一版实现                                           |
| -------------- | ---------------------- | ---------------------------------------------------- |
| 透色基底       | 透出背景，稳定文字对比 | 延续已有材质颜色、模糊、折射与用户参数               |
| 弧面肩部       | 表现表面的转折         | 上方 7px 内柔和亮面，下方 4px 内暗面                 |
| 定向边缘       | 表现受光方向           | 局部亮边过渡到透明，再接暗边；避免整圈等亮白线       |
| 表面反光       | 保持高光清晰           | 内容卡片不使用光照图；播放栏不使用                   |
| 接触与悬浮阴影 | 区分厚度和高度         | 近影 0 2px 5px，远影 0 12px 32px；深浅色使用不同强度 |

基础光影统一放在 `src/renderer/src/assets/bohr.css`。内容卡片使用普通主题表面，不生成折射或高光贴图；歌曲列表保留单层、同色的原生圆角描边。播放栏仅保留透色、背景模糊、折射与外侧阴影；移除专用光学装饰节点和高光贴图生成，材质调节不再带回边缘光。标准播放栏的进度区域相对原位置下移 5px，播放按钮为 40px 高；拖动命中区域保持独立。

## 清晰度与流畅度

- [Apple 高分辨率渲染指南](https://developer.apple.com/library/archive/documentation/GraphicsAnimation/Conceptual/HighResolutionOSX/Optimizing/Optimizing.html)强调自绘内容匹配屏幕像素密度。Web 内容由 Chromium 自动处理；应用生成的玻璃贴图则必须自行处理采样密度。
- 保留的播放栏折射贴图使用采样规则：至少 2 倍采样，随屏幕 DPI 提升至 3 倍；单轴不超过 2048 像素、单张不超过 2097152 像素（解码 RGBA 上限 8 MiB）。超限时等比限制采样，保留光学半径和折射宽度。
- 轮廓像素使用 4 × 4 覆盖率积分，折射图保持全不透明，避免预乘透明度破坏中性色通道。透明内区直接填充，直线边缘复用相同光学结果；保留逐像素抖动，不改变渐变输出。
- 跨显示器 DPI 变化单独监听，即使 CSS 尺寸没有变化也更新贴图。更新仍走原有 120ms 合并调度及各 8 项缓存，不在鼠标移动时生成贴图；缓存按有效尺寸区分并更新使用顺序。
- 歌曲列表的播放描边改用原生圆角边框，保留既有色系与选中状态；歌词行及字符取消长期 `will-change: transform`，由实际动画管理合成生命周期。[Chromium 动画指南](https://web.dev/articles/animations-guide)建议仅在必要时使用该提示；[重采样说明](https://developer.chrome.com/blog/re-rastering-composite)解释了持续缓存与缩放清晰度的取舍。
- 保留硬件加速偏好、字体渲染偏好和现有无障碍回退，不添加全局强制 GPU、MSAA 或 `translateZ(0)` 开关。
- 播放栏没有描边、内侧亮光或边缘渐变，以等量内边距保留原布局空间；折射层与根容器共用外轮廓。封面图片取消自身圆角，由容器统一裁切，包含悬停缩放。重复裁切会相乘边缘覆盖率，提高贴图采样无法修复这一层问题。
- 独立 Electron 像素回归将播放栏基底与封面裁切同几何的单层原生输出对比，覆盖深浅色、三种材质、六档 DPI、整数／小数位置及封面静态／悬停，共 144 个渲染情形。完整材质检查另覆盖 36 帧，验证实际背景滤镜、输入命中及无边缘光状态；不再保留已删除光照层的连续性测试。

这些改动以 Windows Electron 的实际渲染验证为准，尚未对 iOS/macOS 原生应用做帧率或视觉等价性比较。

同密度生成基准在 Windows Node 中预热后各运行 7 次，取两张贴图合计的中位耗时：1180 × 72 播放栏约 105 → 12ms，320 × 320 卡片约 100 → 7ms（2 倍采样）。比较对象是逐像素计算与内区／直边复用，两者 RGBA 逐字节一致；不包含 PNG 编码、GPU 合成或整机帧率。

## 使用范围

- **标题栏**：附着于窗口的透色层，无底部描边或硬边阴影；高度仍为 40px。播放页继续沉浸，不叠加浮动玻璃边框。
- **设置导航**：启用液态玻璃时使用常规扩散与统一浮层阴影，优先保证阅读；正文维持原有内容面板。
- **标准播放栏**：独立浮动的透色层，不绘制边缘光；默认约 80px 高；普通页面浮动，歌曲详情页以透明控制层贴底。
- **迷你与紧凑播放栏**：保持独立的平面条带语言，不加入标准播放栏的弧面层。

设置中显示“液态玻璃”，存储值继续使用 `liquidGlass`。既有主题、材质设置和插件接口无需迁移；用户可在背景与界面材质编辑器中选择并预览。

## 回退与验证

### 播放栏的合成与导航层级

- [Chromium 背景滤镜实现说明](https://github.com/mfreed7/backdrop-filter-feature/blob/master/README.md)解释了读取背景纹理、过滤、圆角裁切和合成的过程。单独验证边框或高光不足以说明完整玻璃材质的效果，需验证实际启用的背景扩散与折射，不能只检查孤立的边框。
- [Filter Effects Level 2 编辑草案](https://drafts.csswg.org/filter-effects-2/)描述了滤镜输出按圆角边界裁切的模型，以及滤镜、遮罩对背景采样边界的影响。该文档仍在讨论中；本项目以当前 Windows Electron 的实际输出作为验证依据。
- 明确指定真实 DPI 的完整材质测试检出了 125% 缩放下的静态轮廓错位：CSS 的 1px 透明边框会对齐到物理像素，实际宽度可能为 0.8px；高光和折射层固定的 `inset: -1px` 因此超出根容器，形成不同心的多层边缘。标准播放栏移除占位边框，以等量内边距维持默认控件几何；折射改为 `inset: 0`，与基底共用实际外轮廓；后续按视觉反馈删除高光层。
- 本次确认的动态问题来自应用逻辑：侧栏展开会改变播放栏的左边距和宽度、将层级从 1002 降到 999，并在 340ms 内停用背景模糊。布局重采样与材质切换叠加，导致侧栏切换时播放栏跳动和边缘观感变化。现移除这条链条，标准与迷你形态保持窗口边距，紧凑形态保持全宽；播放栏保持在侧栏 1000 层级之上。侧栏仅根据实际重叠预留底部空间。自定义主题的网格位置继续由主题管理。
- [Electron #53810](https://releases.electronjs.org/pr/53810)修复过离屏窗口 `capturePage()` 按显示器缩放重采样的问题，43 系列修复版本为 43.7.1。本项目当前使用 43.5.0；这说明需要纠正截图测试路径，不能据此断言普通应用窗口的锯齿由同一个缺陷造成。
- 普通隐藏窗口在本机的物理像素截图会超时，因此仅用于初始材质行为检查。像素测试为每个 DPI 创建明确指定 `offscreen.deviceScaleFactor` 的隔离窗口，校验实际 `devicePixelRatio` 和截图尺寸，避免按显示器密度二次放大。完整材质测试覆盖深浅色、常规／玻璃／折射三种路径与 1–3 倍 DPI，检查实际滤镜仍然启用，播放栏不再生成边缘高光。侧栏动画逐帧检查三种播放栏的四项几何、材质连续性与重叠区域命中。

本轮未使用 Computer Use。这些隔离渲染测试可以发现裁切、材质状态和导航耦合回归，仍不能替代用户显示器上对残余锯齿的视觉确认，也不宣称低 DPI 圆角完全没有像素阶梯。

全透明材质隐藏折射与阴影，恢复玻璃后重新显示透色基底，控件几何不变。关闭模糊、降低特效、减少透明度、高对比度及强制系统颜色时沿用可读性回退。旧内容卡片玻璃参数保留在存储格式中，运行时统一退回普通内容材质。

验证包含真实 Electron 深浅色渲染、点击命中、材质切换、无障碍回退与进度拖动。全窗口预览保留设置导航状态，只临时显示原页面；取消恢复原偏好。Windows Computer Use 验证实际播放控件与从设置进入预览的流程。

## 2026-10-12：内容材质与渲染资源检查

- 依据 [Apple HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials)，液态玻璃仅用于导航和控制层。首页焦点、专辑及其他内容卡片保留普通主题表面、封面背景、阅读遮罩与原有圆角，不叠加折射、高光或指针跟随。设置移除扩展实验与首页玻璃入口；存储格式保持兼容，旧参数不再启用内容光学层。
- 光学定义从四条滤镜减为一条播放栏滤镜。删除内容贴图生成、全局卡片指针监听、卡片可见性预算与内容树观察器；没有真实播放栏、歌曲详情贴底模式、迷你／紧凑栏或关闭模糊时不启用播放栏贴图组件。窗口尺寸变化继续使用 120ms 合并与有上限的贴图缓存。
- 材质环境仅采样真正的页面背景，不再监听整棵内容树或以首页封面替代标题栏背景。背景图片加载可取消，8 秒超时；切换来源、关闭材质或卸载时释放加载任务、事件与定时器。采样继续拒绝网络、可执行及任意文件 URL，保持原 CSP 和沙箱边界。
- Electron 资源回归覆盖 200 张内容卡片、2000 次内容变更、40 次材质开关和尺寸变化；内容变化不触发播放栏观察器或生成新贴图，停用及卸载后观察器归零。另保留深浅色、六档 DPI 的完整播放材质与标题栏回退验证。
- 这些证据证明相关渲染工作受到限制、资源可释放，不代表已测得整机恒定帧率或完成全应用安全审计。Windows 外跳、IPC 输入、音频来源和预加载沙箱保持既有安全校验。

## 2026-10-12：播放栏留白与标题栏反馈

- 参考 [Apple HIG Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars) 的分组、留白与一致反馈，以及 [Color](https://developer.apple.com/design/human-interface-guidelines/color) 对玻璃上克制用色的建议。标题栏保留应用工具和 Windows 窗口控制的分组；设置、扩展和通知使用统一的内收圆角底色与选中图标色，不增加独立玻璃层或描边。
- 应用工具保留 46 × 40px 点击范围，视觉反馈内收为 32 × 30px；键盘焦点继续可见，高对比度和强制颜色保持选中状态可辨识。这里的像素值是 Windows 应用的布局选择，并非 HIG 规定。
- 普通标准播放栏距底边由 14px 调整为 22px。歌曲详情的贴底模式和迷你、紧凑及自定义窗口布局沿用原有定位；内容避让继续读取实际播放栏位置。
